# حسابینو V30 Ultimate

نسخه بازآرایی‌شده بر پایه فایل ارسالی شما. رابط وب از فایل یکپارچه به `index.html`، `styles.css` و `app.js` جدا شده است؛ منطق اصلی موجود حفظ شده و فایل‌های PWA و آیکون‌ها نیز همراه پروژه هستند.

## وضعیت و محدودیت مهم
- بررسی نحوی JavaScript با Node.js انجام شده است.
- تست دود (smoke test) ساختار فایل‌ها و چند شرط پایه را بررسی می‌کند؛ این تست جایگزین تست کامل دستیِ تمام محاسبات مالی نیست.
- این بسته هنوز APK از پیش کامپایل‌شده ندارد. Workflow زیر پروژه Android را در runner گیت‌هاب با Capacitor ایجاد و APK آزمایشی Debug را می‌سازد.
- نسخه Debug برای تست است و به معنی APK انتشار فروشگاهیِ امضاشده نیست.
- داده‌های مالی در ذخیره‌سازی محلی دستگاه می‌مانند؛ پاک‌شدن داده‌های مرورگر/برنامه یا خرابی دستگاه می‌تواند باعث از دست رفتن داده شود. مرتب پشتیبان JSON بگیرید.
- اعلان‌های زمان‌بندی‌شده در مرورگر بسته تضمین نمی‌شوند؛ در نسخه وب فقط آنچه مرورگر پشتیبانی کند در دسترس است.
- فایل `sw.js` برای کش فایل‌های وب است. PWA و Service Worker باید از HTTPS ارائه شوند (GitHub Pages این شرط را دارد).

## اجرای محلی برای بررسی
به پوشه پروژه بروید و اجرا کنید:

```bash
npm install
npm test
```

برای اجرای سایت می‌توانید از یک وب‌سرور محلی استفاده کنید. بازکردن مستقیم `index.html` با `file://`، قابلیت نصب PWA و Service Worker را فعال نمی‌کند.

## انتشار روی GitHub Pages
1. یک مخزن جدید در GitHub بسازید.
2. تمام محتویات این پوشه را در ریشه مخزن بارگذاری کنید (نه خود پوشه به‌عنوان یک زیرپوشه).
3. به `Settings > Pages` بروید.
4. در بخش `Build and deployment`، گزینه `Deploy from a branch` را انتخاب کنید.
5. شاخه `main` و پوشه `/(root)` را انتخاب و ذخیره کنید.
6. چند دقیقه بعد آدرس Pages را باز کنید. پس از هر تغییر، کش Service Worker ممکن است به چند لحظه برای به‌روزرسانی نیاز داشته باشد.

## ساخت APK از GitHub Actions
1. فایل‌های پروژه را در مخزن قرار دهید.
2. وارد تب `Actions` شوید.
3. Workflow با نام **Build Android APK** را انتخاب کنید.
4. روی `Run workflow` و سپس اجرای شاخه `main` کلیک کنید.
5. پس از سبز شدن اجرا، پایین صفحه همان اجرا بخش `Artifacts` را باز کنید و `hesabino-debug-apk` را دانلود کنید.
6. ZIP دانلودشده را باز کنید و APK را روی گوشی نصب کنید. ممکن است لازم باشد به مرورگر/مدیر فایل اجازه نصب برنامه ناشناس بدهید.

Workflow فایل‌های وب را در `www/` کپی می‌کند، پروژه Android را با Capacitor تولید می‌کند و `assembleDebug` را اجرا می‌کند. برای ساخت روی runner به اینترنت جهت دریافت پکیج‌ها و ابزارهای Android نیاز است.

## امضای نسخه انتشار
APK خروجی Debug برای انتشار عمومی توصیه نمی‌شود. برای نسخه Release باید keystore اختصاصی بسازید و فایل keystore و رمزهای آن را خارج از مخزن نگه دارید. برای اتوماسیون امن، keystore به صورت Base64 و رمزها به‌عنوان GitHub Actions Secrets ذخیره می‌شوند و Workflow جداگانه‌ای باید آن‌ها را در زمان ساخت به‌صورت موقت بازیابی کند. کلید امضا را در مخزن عمومی یا داخل ZIP عمومی قرار ندهید؛ گم‌شدن کلید می‌تواند انتشار به‌روزرسانی با همان شناسه برنامه را دشوار کند.

## پشتیبان‌گیری
از داخل برنامه، از قابلیت پشتیبان‌گیری JSON استفاده کنید و فایل را در یک محل امن نگه دارید. قبل از بازیابی، مطمئن شوید فایل متعلق به حسابینو است. پشتیبان ممکن است شامل اطلاعات مالی خصوصی باشد؛ آن را عمومی یا برای افراد دیگر ارسال نکنید.

## ساختار
- `index.html`: پوسته و محتوای برنامه
- `styles.css`: استایل و واکنش‌گرایی
- `app.js`: منطق برنامه
- `manifest.json`: تنظیمات نصب PWA
- `sw.js`: کش و تجربه آفلاین محدود
- `icon-192.png`, `icon-512.png`: آیکون‌های PWA
- `mascot.svg`: تصویر شخصیت
- `.github/workflows/build-android-apk.yml`: ساخت APK آزمایشی
- `tests/smoke-test.js`: تست ساختار پایه

## مجوز و حریم خصوصی
پیش از انتشار عمومی، وابستگی‌ها و حقوق استفاده از فونت‌ها/آیکون‌ها را بررسی کنید. این برنامه مشاور مالی حرفه‌ای نیست و خروجی‌ها را بر اساس داده‌های واردشده محاسبه می‌کند.
